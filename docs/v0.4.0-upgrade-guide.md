# Upgrade Guide: v0.3.0 to v0.4.0

This guide covers breaking changes when upgrading to v0.4.0 of the MongoDB Atlas AWS module. The module remains in public preview; treat upgrades as you would any pre-v1 module.

- [Module-managed KMS multi_region default (Breaking Change)](#module-managed-kms-multi_region-default-breaking-change)

## Module-managed KMS multi_region default (Breaking Change)

`create_kms_key.multi_region` now defaults to `true` so a new module-managed Customer Master Key (CMK) can grow replicas later. AWS cannot convert a single-Region key to multi-Region in place (`aws_kms_key.multi_region` is ForceNew).

### Who is affected?

Stacks on v0.3.0 with `create_kms_key.enabled = true` that did not set `multi_region`. Those keys are single-Region. Without the pin below, Terraform replaces the CMK.

Atlas encrypts cluster data with its own data keys wrapped by the KMS CMK, so adding a new project CMK does not cause cluster downtime. The limitation is backups taken under the old key; see [State migration](#state-migration).

Stacks that already set `multi_region`, or that use BYO `kms_key_arn`, are not affected.

### Required action

Pin `multi_region = false` **before** upgrading. That keeps the existing key and also skips replica-region inference:

```terraform
module "atlas_aws" {
  source     = "terraform-mongodbatlas-modules/atlas-aws/mongodbatlas"
  version    = "~> 0.4"
  project_id = var.project_id

  encryption = {
    enabled = true
    create_kms_key = {
      enabled      = true
      multi_region = false
    }
  }
}
```

Without the pin, `terraform plan` replaces the key:

```
-/+ destroy and then create replacement

# module.atlas_aws.module.encryption[0].aws_kms_key.atlas[0] must be replaced
      ~ multi_region = false -> true # forces replacement
```

Replace `atlas_aws` with your module label.

### State migration

To keep the old key in AWS and create a new multi-Region key, remove the resource from state before apply:

```bash
terraform state rm 'module.atlas_aws.module.encryption[0].aws_kms_key.atlas[0]'
```

Apply then creates the new key. The old key stays in AWS. If destroy runs, `deletion_window_in_days` is 7 by default (AWS minimum). You can cancel deletion in that window and restore backups that used the old CMK.

Flipping `multi_region` from `false` to `true` later is a new key plus an Atlas CMK swap, not an in-place change.

### Why the change?

Atlas encryption at rest with AWS KMS requires the CMK in every region where the cluster has nodes. A multi-Region primary can add `aws_kms_replica_key` resources without replacing the primary.
